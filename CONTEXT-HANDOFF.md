## 0. What this project is

A pure-Rust, `#![forbid(unsafe_code)]` algorithm-for-algorithm port of **SVT-AV1
v4.2.0**. The bar is not "it encodes" — it is **byte-identical OBUs to the C
encoder at a matched config**, proven cell by cell against the real
`libSvtAv1Enc` built from the `reference/svt-av1` submodule. Everything below
assumes that bar.

It is **no longer still-image-only.** The all-intra (AVIF / still) path has been
byte-identical across its tested envelope since 2026-07; since 2026-08-31 an
**inter campaign** has been running, and the inter path now encodes video-mode
key frames *and* inter frames byte-identically to C over a 96-cell grid, plus
the whole p0–p4 synthetic band since global motion landed (§3).

**Two things that are still true and are easy to misread:**

* The **shipped public API still refuses non-key frames.** `EncodePipeline`
  returns a typed refusal; `SVTAV1_INTER_EXPERIMENTAL=1` lifts it **for the
  differential harness only** and must never leave `tools/`. See
  `rust/docs/WORKING-ON-THIS.md` §7b.
* Refusing beats emitting a plausible-but-wrong stream. A refusal is not a
  solution, though — every one is catalogued with what C does with that config
  (`rust/docs/REFUSED-CONFIGS.md`, generated by `tools/refusal_inventory.sh`).

**The goal, as the user set it on 2026-09-02 — four axes:** complete inter
encoding, **bit-exact** with C, at the **same tuning parameters**, with **CPU and
memory within 25 % of C**. Where each stands: §3.

## 2. Get it building on a fresh box

```bash
git clone --recurse-submodules https://github.com/imazen/zenav1-svt
cd zenav1-svt && git submodule update --init --recursive
```

Prerequisites: a stable Rust toolchain (workspace MSRV 1.85, 2024 edition),
`cmake` + a C compiler (+ `nasm` on x86; `ninja` optional), and
`cargo install cargo-nextest just`.

**The C oracle is built BY CARGO.** `rust/crates/svtav1-cref/build.rs`
configures and builds **both** variants on first use, keyed on the submodule
commit: `Bin/Release` (mainline, `SVT_HDR_MODE=OFF`) and `Bin/ReleaseHdr` (the
HDR fork, `=ON`). Knobs: `SVT_CREF_LIB_DIR=<dir>` links a prebuilt
`libSvtAv1Enc.a` and builds nothing; `SVT_CREF_SKIP_HDR=1` skips the fork
variant. Most gate scripts default `SVT_CREF_LIB_DIR` to `<repo>/Bin/Release`
themselves.

```bash
cd rust && cargo build -p zenav1-svt-cref     # or just: cargo nextest run --workspace
export SVT_CREF_LIB_DIR=$(pwd)/../Bin/Release
```

**A reference decoder is required** by the recon / decode / IntraBC gates — there
is no fallback and no graceful skip. Build `aomdec` from libaom (`-b v3.12.1`,
`-DCONFIG_AV1_ENCODER=0 -DENABLE_EXAMPLES=1`, target `aomdec`) and pass it as
`AOMDEC=` / `RS_AOMDEC=`; `DAV1D=$(command -v dav1d)` for `decode_conformance.sh`.

**Corpora.** The real-content and screen-content gates need
[`imazen/codec-corpus`](https://github.com/imazen/codec-corpus) — on the dev
boxes at `~/work/zen/codec-corpus` (`CID22/CID22-512`, `gb82`, `gb82-sc`).
`rust/tools/lib_corpus.sh` resolves it via `$ZENAV1_CORPUS_ROOT`, then
`$HOME/work/zen`, `/root/work`, `$HOME/work`. **CI now fetches `gb82-sc` itself**
(blob-filtered sparse clone, 2.9 MB, 10 PNGs, asserted) — before 2026-09-05 the
screen band was guarded by nothing on the runner.

**Two hosts, and the split matters.**

* **This Mac** (aarch64, M4 Pro): the primary checkout, the gate chains, the
  aarch64 wall-clock and `mem_peak`/`mem_bisect` arms. `/bin/bash` here is 3.2 —
  see §4.
* **`ssh r7900x`** (x86_64-linux): callgrind (`Ir`), `perf stat`/`perf record`
  hardware counters, `heaptrack`, and the x86 cross-ISA gate leg. Every kernel
  claim is expected on both ISAs.
* The oracle: the submodule is `imazen/zenav1-svt-c`; the campaign's base is the
  formerly-detached commit **`3115c0c`**, now preserved as branch
  `oracle-base-hdr-fork`. The working tree on the boxes may sit on
  `fix/suspected-c-bug-17` while the outer pin still reads `3115c0c` — see the
  TRAP box in `rust/docs/WORKING-ON-THIS.md` §4 before reproducing a number.

## 4. Running the gates

```bash
cd rust
cargo nextest run --workspace -j 4      # ~3s. NOT `cargo test`; NOT `cargo test --release`.
tools/regression_spotcheck.sh           # ~90s, one cell per bug ever fixed
```

That is the inner loop; both must be green before anything else. Then, per what
you touched:

```bash
tools/identity_full_8bit.sh                 # ~25 min, 1100 cells (synthetic + dims)
IF_TIER=real tools/identity_full_8bit.sh    # ~45 min, needs the corpora
tools/inter_byte_gate.sh                    # the 108-cell inter byte gate
tools/inter_byte_matrix.sh                  # the full 96-cell grid (scoreboard)
SCAN_GATE=1 tools/inter_completion_scan.sh  # completion scan AS A GATE (plain inventory by default)
tools/video_key_matrix.sh                   # video-mode KEY frame scoreboard
tools/screen_ibc_byte_gate.sh               # needs gb82-sc
tools/perf_gate.sh ; tools/mem_gate.sh 6    # wall clock / peak RSS, port vs C
python3 tools/coverage_matrix.py            # what is COVERED — read before any pass rate
```

**`/bin/bash` on this Mac is 3.2 and that is a correctness issue, not a style
one.** `mapfile` / `readarray` / `declare -A` do not exist there; a gate that
iterates a `mapfile` array silently iterates **nothing** and prints PASS. Every
gate that uses them now refuses to run on bash < 4 (`FATAL: needs bash >= 4`,
exit 2) — run them under Homebrew's bash: `/opt/homebrew/bin/bash tools/<gate>.sh`.
Thirteen gates were found in 2026-09-04 to have been unable to report at all.

Two more reading rules: `identity_matrix.sh` is a tracking **scoreboard** that
always exits 0 — read its tally, not `$?`. And a gate whose corpus is missing may
run a reduced cell set: check the printed count against the documented one.

**The debugger is `tools/identity_diff.sh <w> <h> <qp> <preset> <content>`** — it
runs both encoders and names the FIRST divergence with its stage (sequence-header
field / frame-header field / tile-op index + symbol). `tools/identity_diff_inter.sh`
is the video-mode sibling (never call it directly for frame 1 — see §5's list);
`tools/drill_cell.sh` dumps both decision trees for one cell.

## 5. Traps — the list is `rust/docs/WORKING-ON-THIS.md` §5, read it

Each entry there produced a confident wrong answer in a single day. Do not
re-derive them. The four that cost the most, named here so you cannot miss them:

* **`tools/perf_ab.sh` does not read 1.000 on no change.** A same-binary
  base-vs-base control reads 0.995–0.997× — a 0.3–0.5 % bias against the
  candidate slot, and it is the HARNESS, not box contention (measured again on a
  quiet box). **Every A/B needs a same-binary control run in the same session,
  reported next to the candidate rows.** Two rounds once went into hunting a
  regression that did not exist. It is also not constant: measure it per binary
  pair rather than borrowing another lane's number.
* **valgrind masks AVX-512**, so every callgrind number for C is **C's AVX2
  arm** — and C really does run AVX-512 kernels on r7900x. Ir rankings are still
  usable in aggregate (C's hardware instruction count is ~5 % below its callgrind
  Ir) but per-kernel they can be badly off, and an AVX-512 archmage tier is
  headroom no Ir number in this campaign can price.
* **`until ! pgrep -f <script>` matches itself and never exits.** The waiter's own
  command line contains the pattern. Match the script path, watch the log's
  completion line, or use a pid.
* **`tools/perf_gate.sh` overwrites `rust/.workongoing`** with a hard-coded
  `claude-perf-g4` id every cell, to keep the marker fresh across a long sweep —
  so a perf sweep silently steals another lane's claim. Re-claim after running it.

Also worth knowing before your first day ends: one harness invocation per
checkout at a time (`identity_run` rebuilds per call and overlapping runs can
execute a binary the other is rewriting); `cargo test --release` is **not** the
gate (nextest builds debug, where arithmetic overflow panics); the C submodule is
a **symlink** inside every `jj workspace add` sibling, which breaks the container
trace driver until it resolves the path.

## 7. Working here

`~/.claude/CLAUDE.md` governs. The parts that bite in this repo:

* **jj on a colocated git repo, work on `main`, no feature branches.** Parallel
  lanes each take their own `jj workspace add --name <lane> ../zenav1-svt--<lane>
  -r main@origin`; one shared checkout means every lane's commit sweeps the
  others' in-flight files.
* **`.workongoing` at the repo root** is the claim; refresh it every ~2 minutes,
  delete it when you stop, and never clear another lane's. Stale markers from
  dead lanes accumulate — check the timestamp before assuming a repo is busy.
* **Rebase before pushing** (`jj git fetch && jj rebase -d main@origin`), then
  `jj bookmark set main -r @ && jj git push --bookmark main`, then verify with
  `git merge-base --is-ancestor <sha> origin/main`. Never `jj git push --change`.
* Scratch goes in `~/tmp`, never `/tmp` — a mid-session wipe has already
  destroyed a measurement harness here. Anything that took real work to build
  belongs in the repo (`rust/tools/`, `rust/benchmarks/`), not in scratch.
* Every measurement that informs a claim gets a committed record under
  `rust/benchmarks/<name>_<YYYY-MM-DD>.{tsv,meta}` — the `.meta` carries the
  commit, host, grid and method. A number without a record is not evidence.
